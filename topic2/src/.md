
# C++ 物流系统代码问题汇总

## 1. `protected` 访问控制的作用

**问题**：为什么使用 `protected` 而不是 `private`？

**解答**：
- `protected` 允许子类（派生类）访问成员，但禁止外部代码访问
- `private` 连子类也不能访问
- 作用：在封装性和继承便利性之间取得平衡，让子类可以直接操作基类成员，避免写大量 getter/setter

---

## 2. 子类构造函数的执行顺序

**问题**：子类构造函数优先调用谁的？

**解答**：
- **先调用基类构造函数**（初始化继承来的属性）
- **再初始化子类自己的新属性**
- 析构顺序相反（先子类后基类）

```cpp
子类名(基类参数, 自己的参数)
    : 基类名(基类参数),  // 先调用基类构造
      自己的属性(自己的参数)  // 再初始化新属性
{}
```

---

## 3. 父类和子类函数重复问题（`AddBalance` vs `AddCompanyBalance`）

**问题**：父类有 `AddBalance()`，子类为什么还要写 `AddCompanyBalance()`？是否重复？

**解答**：
- 如果 `Admin` 代表公司本身，则子类不需要额外函数，直接用父类的 `AddBalance()`
- 如果公司余额和管理员个人余额是两个独立概念，则需要在子类中添加新的成员变量和对应的函数
- 关键：看语义是否相同

---

## 4. `Admin` 是否需要继承 `Person`？

**问题**：如果 `Admin` 代表公司，直接用 `Person` 不行吗？继承是否多余？

**解答**：
- **需要继承**：避免重复代码，复用 `Person` 的属性和方法
- 继承表达"管理员也是一种用户"的关系
- 但管理功能（`viewAllUsers` 等）可以放在独立的 `AdminController` 中，实现职责分离

---

## 5. 管理功能放哪里？是否要拆出 `AdminController`？

**问题**：`viewAllUsers()`、`viewAllPackages()` 这些管理功能放 `Admin` 类还是单独的 `AdminController`？

**解答**：
- **放 `Admin` 类**：简单直接，适合小项目
- **放独立的 `AdminController`**：职责更清晰，便于扩展，适合大项目
- 没有绝对对错，取决于系统规模和扩展需求

---

## 6. 一个类拆分成多个 `.cpp` 文件

**问题**：能否一个头文件对应多个 `.cpp` 实现文件？

**解答**：
- **可以**，这叫"按职责拆分实现文件"或"逻辑分组"
- 一个类的实现可以分散在多个 `.cpp` 中
- 适用场景：类非常大（几千行代码时）
- 小项目不建议这样做，会增加复杂度

---

## 7. 多少个文件比较好？如何安排类？

**问题**：项目文件结构如何设计？

**解答**：
- **黄金原则**：一个类 = 一个 `.h` + 一个 `.cpp`
- 5-10个类的项目，10-20个文件是正常的
- 不要过度拆分，保持简单

**物流系统建议结构**：
```
├── Person.h / Person.cpp      // 基类
├── User.h / User.cpp          // 普通用户
├── Admin.h / Admin.cpp        // 管理员
├── Package.h / Package.cpp    // 快递
└── LogisticsSystem.h / LogisticsSystem.cpp  // 主系统
```

---

## 8. Controller 中的 `DataManager& dataManager_`

**问题**：为什么 `AdminController` 中要有 `DataManager& dataManager_`？

**解答**：
- Controller **不存储数据**，只**操作数据**
- 通过引用持有 `DataManager`，可以访问和修改核心数据
- 避免拷贝，多个 Controller 共享同一个数据源

---

## 9. 是否需要 `PersonController`？

**问题**：有 `AdminController`，是否也要有 `PersonController`？

**解答**：
- **不需要**
- `Person` 只是数据模型（基类），不应该负责操作逻辑
- `User` 的操作放在 `User` 类里
- `Admin` 的管理操作放在 `AdminController` 里
- 保持简单，不要过度设计

---

## 10. `auto` 类型推导

**问题**：`auto` 是什么？为什么可以调用函数？

**解答**：
- `auto` 是**类型占位符**，让编译器自动推导变量类型，**不是函数**
- 不能直接调用 `auto.empty()`，应写为 `auto var = ...; var.empty();`
- 常用于：迭代器、模板、lambda表达式、简化复杂类型

---

## 11. `DataManager` 构造和析构函数

**问题**：为什么需要构造和析构函数？

**解答**：
- **构造函数**：对象创建时自动调用，用于初始化（如加载数据）
- **析构函数**：对象销毁时自动调用，用于清理资源（如释放动态内存、保存数据）
- `loadData()` 中先清空旧数据再加载，防止数据重复和内存泄漏

---

## 12. `findWaitingCollectPackages()` 返回值

**问题**：返回的 `result` 包含所有包裹信息吗？

**解答**：
- **不是**，只包含**状态为"待揽收"的包裹指针**
- 是包裹全集的一个**筛选子集**
- 其他状态的包裹（运输中、已签收）不会被加入

---

## 13. `~DataManager()` 中的清理操作

**问题**：为什么要 `delete` 每个包裹，然后 `clear()`？

**解答**：
- `packages_` 存储的是**指针**，需要手动 `delete` 释放内存
- 如果不 `delete`，会造成**内存泄漏**
- `clear()` 清空指针容器，避免悬空指针

---

## 14. `getCurrentCourier()` 和 `isLoggedIn()` 的作用

**问题**：这两个函数是干什么用的？

**解答**：
- `getCurrentCourier()`：获取当前登录的快递员对象（指针）
- `isLoggedIn()`：检查快递员是否已登录（返回 `bool`）
- 作用：对外暴露私有状态，让其他类可以访问当前登录信息

---

## 15. 输入验证代码重复问题

**问题**：`std::cin.fail()` 处理代码重复出现，如何优化？

**解答**：
- 封装成通用函数：`getInt()`、`getIntList()`、`getDouble()` 等
- 创建独立的 `InputHelper` 工具类
- 优点：减少重复，统一错误处理逻辑

---

## 核心设计建议总结

| 问题 | 建议 |
|------|------|
| 类拆分 | 不要过度拆分，1个类 = 1对 `.h/.cpp` |
| Controller | 小项目不需要，一个 `LogisticsSystem` 足够 |
| 继承 | 用 `protected` 让子类访问基类成员 |
| 构造函数 | 子类要显式调用基类构造函数 |
| 动态内存 | 记得在析构函数中 `delete` |
| 重复代码 | 封装成通用函数或工具类 |
```
