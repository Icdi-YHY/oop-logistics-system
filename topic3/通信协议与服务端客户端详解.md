## 二、通信协议层（Protocol.h）

### 2.1 定位

`include/Protocol.h` 是 **Client 和 Server 共同遵守的"合同"**，定义了：
- 请求/响应的**文本格式**
- 所有**命令常量**（两端说同一种语言）
- 4 个 **辅助构建函数**（组装报文）

两端各是一个独立 exe，但 `#include "../include/Protocol.h"` 共用同一份头文件。

### 2.2 报文格式

```
请求格式:
  COMMAND|param1|param2|...\n

响应格式 (成功):
  OK|message\n
  data_line1\n
  data_line2\n
  END\n

响应格式 (失败):
  ERR|message\n
```

**设三个关键符号：**

| 符号 | 含义 | 为什么选它 |
|------|------|-----------|
| `|` | 参数分隔符 | 肉眼可读、不用转义、比 `,` 少歧义 |
| `\n` | 消息边界 | `getline()` 天然按行拆包 |
| `END` | 数据结束标记 | Client 知道多行响应何时读完 |

### 2.3 三层响应

```cpp
// ① 简单成功 — 返回一行消息
buildOkResponse("密码已修改")
→ "OK|密码已修改\n"

// ② 带数据的列表 — 标题 + 多行数据 + 结束标记
buildDataResponse("所有包裹", data.str())
→ "OK|所有包裹\n1|alice|bob|...|已签收\n2|...\nEND\n"

// ③ 错误
buildErrResponse("未找到用户")
→ "ERR|未找到用户\n"
```

Client 的 `printResponse()` 就按这 3 种格式解析展示。

### 2.4 命令常量表（词汇表）

定义了 30+ 个命令，每种操作一个标准化名称：

| 角色 | 命令常量 | 对应操作 |
|------|---------|---------|
| **通用** | `CMD_LOGIN` / `CMD_REGISTER` / `CMD_LOGOUT` / `CMD_EXIT` | 登录/注册/登出/退出 |
| **用户** | `CMD_SEND_PACKAGE` | 发送快递 |
| | `CMD_RECEIVE_PACKAGE` | 接收/签收快递 |
| | `CMD_QUERY_SENT` / `CMD_QUERY_RECEIVED` | 按收发方查询 |
| | `CMD_QUERY_BY_ID` | 按单号查询 |
| | `CMD_QUERY_BY_TIME_SENT` / `CMD_QUERY_BY_TIME_RECEIVED` | 按时间查询 |
| | `CMD_GET_BALANCE` / `CMD_RECHARGE` / `CMD_CHANGE_PWD` | 余额/充值/改密 |
| **管理员** | `CMD_ADMIN_SHOW_USERS` / `CMD_ADMIN_SHOW_PACKAGES` | 查看用户/包裹 |
| | `CMD_ADMIN_SHOW_BALANCE` | 查看公司余额 |
| | `CMD_ADMIN_ADD_COURIER` / `CMD_ADMIN_REMOVE_COURIER` | 增删快递员 |
| | `CMD_ADMIN_SHOW_COURIERS` / `CMD_ADMIN_SHOW_COURIER_DETAIL` | 查看快递员 |
| | `CMD_ADMIN_ASSIGN_COURIER` | 分配揽收任务 |
| | `CMD_ADMIN_QUERY_BY_SENDER` / `CMD_ADMIN_QUERY_BY_RECEIVER` / `CMD_ADMIN_QUERY_BY_ID` / `CMD_ADMIN_QUERY_BY_TIME` | 管理员查询 |
| **快递员** | `CMD_COURIER_MY_TASKS` / `CMD_COURIER_COLLECT` | 查看任务/揽收 |
| | `CMD_COURIER_MY_RECORDS` | 揽收记录 |
| | `CMD_COURIER_BALANCE` / `CMD_COURIER_CHANGE_PWD` | 余额/改密 |

Client **按名称构造请求**，Server **按名称路由**——两端不依赖函数签名，只依赖字符串。

### 2.5 为什么是文本协议，不是二进制？

| 方面 | 文本协议（本项目） | 二进制协议（如 protobuf） |
|------|------------------|------------------------|
| 调试 | `telnet` 直接看报文 | 需要编解码工具 |
| 实现 | `stringstream` 搞定 | 需要序列化库 |
| 性能 | 稍慢（解析开销） | 更快 |
| 适用 | 教学/小型系统 | 高性能生产系统 |

教学项目用文本协议，**每步都能 `cout` 出来看**，是正确取舍。

## 三、服务端核心（Server.cpp）

### 3.1 对象结构

```cpp
class Server {
private:
    SOCKET listenSocket_;       // 监听 Socket
    int port_;                  // 端口号 (8888)
    DataManager dataManager_;   // 数据管理器（内存 + 文件）
    CRITICAL_SECTION cs_;       // 线程锁
    volatile bool running_;     // 运行标志
    int nextClientId_;          // 自增客户端编号
};
```

`Server` 集四个角色于一身：
- **TCP 服务器** — 监听端口、接收连接
- **线程管理器** — 每连接开一个线程
- **请求路由器** — 4 层分发链
- **业务容器** — 持有 DataManager 和所有 handler

### 3.2 生命周期

```
Server server(8888);
   │
   └─ 构造函数
        ├─ InitializeCriticalSection(&cs_)
        └─ dataManager_.loadData()   ← 从文本文件加载所有数据到内存
   │
server.start();
   │
   └─ WSAStartup → socket → bind → listen
        └─ while(running_)
             ├─ accept() → 新连接
             ├─ CreateThread(handleClient, ...)
             └─ 继续等待下一连接
   │
server.stop();
   │
   └─ running_ = false
        └─ closesocket(listenSocket_)  ← 让 accept() 退出
   │
~Server()
   └─ stop() + DeleteCriticalSection()
```

### 3.3 多线程模型

```cpp
// 每 accept 一个客户端，就开一个新线程
while (running_) {
    SOCKET clientSocket = accept(listenSocket_, ...);

    ThreadParam* param = new ThreadParam{this, clientSocket, cid};

    CreateThread(NULL, 0,
        [](LPVOID lpParam) -> DWORD {
            ThreadParam* p = (ThreadParam*)lpParam;
            p->server->handleClient(p->clientSocket, p->clientId);
            closesocket(p->clientSocket);
            delete p;               // 线程退出后自动清理
            return 0;
        },
        param, 0, NULL);
}
```

**特性说明：**

| 特性 | 实现 |
|------|------|
| 并发模型 | **连接-每-线程**（One-Thread-Per-Client） |
| 线程退出 | 客户端断开 → `recv()` 返回 ≤0 → 循环退出 → 线程结束 |
| 内存泄漏防护 | `delete p` 在线程末尾，确保 `ThreadParam` 释放 |
| 为什么用 `CreateThread` | 项目纯 Windows API，无 C++11 线程依赖 |

**每个线程的 `handleClient()` 内部循环：**

```cpp
void Server::handleClient(SOCKET clientSocket, int clientId) {
    int userType = 0;              // 初始：未登录
    std::string sessionUsername;   // 初始：空

    char buffer[8192];
    while (running_) {
        recv(buffer);              // 收一条请求

        istringstream(buffer)      // 按行拆包（可能粘包）
        while (getline → singleRequest) {
            processRequest(singleRequest, userType, sessionUsername);
            //              ↑ 传引用，handleLogin 会修改它
            send(response);
        }
    }
}
```

### 3.4 核心 — 4 层请求分发链

```
processRequest(request, userType, sessionUsername)
  │
  ├─ 解析命令: getline(ss, cmd, '|')
  ├─ 解析参数: while(getline → params[])
  │
  EnterCriticalSection
  │
  ├─ CMD_LOGOUT → userType=0, sessionUsername=""
  │
  ├─ userType==1 → dispatchUserCommand(cmd, params, sessionUsername)
  │                   └─ 匹配 SEND_PACKAGE / RECEIVE_PACKAGE / QUERY_SENT ...
  │
  ├─ userType==2 → dispatchAdminCommand(cmd, params)
  │                   └─ 匹配 ADMIN_SHOW_USERS / ADMIN_ADD_COURIER ...
  │
  ├─ userType==3 → dispatchCourierCommand(cmd, params, sessionUsername)
  │                   └─ 匹配 COURIER_MY_TASKS / COURIER_COLLECT ...
  │
  └─ userType==0 → dispatchUnauthCommand(cmd, params, userType, sessionUsername)
                      └─ LOGIN → handleLogin() → 设置 userType
                      └─ REGISTER → handleRegister()
                      └─ 其他 → "Please login first"
  │
  LeaveCriticalSection
  │
  if needsSave(cmd):
      EnterCriticalSection
      dataManager_.saveData()   ← 写操作后落盘
      LeaveCriticalSection
  │
  return response
```

**关键设计：userType 是传引用进来的**

```
第一次请求:      LOGIN|user|alice|alice123
                 userType=0 → dispatchUnauthCommand → handleLogin()
                 handleLogin 修改 userType=1
第二次请求:      GET_BALANCE
                 userType=1 → dispatchUserCommand → handleBalanceQuery()
```

一次登录，后续请求**自动命中正确的路由**，无需每个 handler 都查身份。

### 3.5 线程安全 — 临界区保护

```cpp
std::string Server::processRequest(...) {
    EnterCriticalSection(&cs_);
    // 所有业务处理
    LeaveCriticalSection(&cs_);

    if (needsSave(cmd)) {
        EnterCriticalSection(&cs_);
        dataManager_.saveData();      // 文件 I/O
        LeaveCriticalSection(&cs_);
    }
}
```

**为什么分两段锁？**

```
线程 A: 发快递    线程 B: 查余额
  │                  │
  ├─ lock            ├─ lock (等待)
  ├─ 修改内存        ├─ ...
  ├─ unlock          ├─ 拿到锁
  │                  ├─ 只读查询 (很快)
  ├─ lock (存文件)   ├─ unlock
  ├─ 写磁盘 I/O      │
  └─ unlock          │
```

如果内存修改和文件保存放在一个大锁里，线程 B 查个余额也要等磁盘写完才能进——不必要的阻塞。

### 3.6 needsSave() — 写操作自动落盘

```cpp
needsSave(cmd) = true 的写操作:
  REGISTER, SEND_PACKAGE, RECEIVE_PACKAGE,
  RECHARGE, CHANGE_PWD,
  ADMIN_ADD_COURIER, ADMIN_REMOVE_COURIER, ADMIN_ASSIGN_COURIER,
  COURIER_COLLECT, COURIER_CHANGE_PWD

needsSave(cmd) = false 的纯查询:
  LOGIN, LOGOUT, EXIT,
  QUERY_SENT, QUERY_RECEIVED, GET_BALANCE,
  ADMIN_SHOW_USERS, ADMIN_SHOW_PACKAGES, ADMIN_SHOW_BALANCE, ...
  COURIER_MY_TASKS, COURIER_BALANCE, ...
```

查询不走 I/O，效率更高。

### 3.7 一次完整请求处理 — "发送快递"端到端

```
TCP 收到: "SEND_PACKAGE|bob|1|3.0|CeramicVase\n"

handleClient() 按行拆包 → "SEND_PACKAGE|bob|1|3.0|CeramicVase"

processRequest() 解析:
  cmd    = "SEND_PACKAGE"
  params = ["bob", "1", "3.0", "CeramicVase"]

  EnterCriticalSection

  userType==1 → dispatchUserCommand()
    → 匹配 CMD_SEND_PACKAGE && params.size()>=4
    → handleSendPackage("alice", "bob", 1, 3.0, "CeramicVase")
        │
        ├─ findUser("bob") → nullptr? → ERR "未找到收件人"
        ├─ findUser("alice") → 查到
        ├─ 检查余额: 200 >= 24 ✓
        ├─ 计算价格: 易碎品 → 8.0 × 3.0 = 24 元
        ├─ alice.DeductBalance(24)   → 余额 200→176
        ├─ admin.AddCompanyBalance(24) → 公司余额 0→24
        ├─ new FragilePackage(...)    → 创建包裹对象
        └─ dataManager_.addPackage()  → 存入内存

  LeaveCriticalSection

  needsSave("SEND_PACKAGE") == true
  EnterCriticalSection
  dataManager_.saveData()   → 写入 packages.txt
  LeaveCriticalSection

  buildOkResponse("包裹已发送！ID：1，费用：24 元，余额：176 元")

send() → TCP 返回客户端
```

## 四、客户端核心（Client.cpp）

### 4.1 对象结构

```cpp
class Client {
private:
    SOCKET sock_;       // 与服务端的 TCP 连接
    bool connected_;    // 连接状态
};
```

对比 Server（~50 行成员声明 + 30+ 函数），Client 只有 **2 个数据成员**，极其轻薄。

### 4.2 Client 的两原子操作

```cpp
// 发送请求
bool Client::sendRequest(const std::string& request) {
    return send(sock_, request.c_str(), request.length(), 0) != SOCKET_ERROR;
}

// 接收响应
std::string Client::receiveResponse() {
    recv(sock_, buffer, sizeof(buffer) - 1, 0);
    return std::string(buffer);
}
```

**每个业务函数 = 拼请求 → 发 → 收 → 展示**：

```cpp
// 查余额 — 最简单，只有一条路
void Client::userBalance() {
    sendRequest(buildRequest(CMD_GET_BALANCE));
    printResponse(receiveResponse());
}

// 发送快递 — 需要收集用户输入
void Client::userSendPackage() {
    string receiver, desc;
    int type;
    double weight;

    cout << "收件人用户名: "; cin >> receiver;
    cout << "快递类型 (1=易碎品 2=图书 3=普通): "; cin >> type;
    cout << "重量/数量: "; cin >> weight;
    cout << "物品描述: "; cin >> desc;

    sendRequest(buildRequest(CMD_SEND_PACKAGE,
        {receiver, to_string(type), to_string(weight), desc}));
    printResponse(receiveResponse());
}
```

### 4.3 响应解析 — printResponse()

```cpp
void Client::printResponse(const string& response) const {
    // ① 错误: "ERR|未找到用户\n"
    if (response.find("ERR") == 0) {
        cout << "错误: " << response.substr(4) << endl;
        return;
    }

    // ② 成功: "OK|标题\n数据行1\n数据行2\nEND\n" 或 "OK|简单消息\n"
    istringstream iss(response);
    string line;
    bool firstLine = true;
    while (getline(iss, line)) {
        if (line == "END") break;              // 多行数据结束
        if (firstLine) {
            auto pos = line.find('|');
            cout << line.substr(pos + 1) << endl;   // 去掉 "OK|"
            firstLine = false;
        } else {
            cout << "  " << line << endl;           // 数据行缩进
        }
    }
}
```

**三种 Server 返回 → Client 展示：**

| Server 返回 | Client 展示 |
|-------------|-----------|
| `OK|密码已修改\n` | `密码已修改` |
| `OK|所有包裹\n1\|alice\|bob\|已签收\nEND\n` | `所有包裹`<br>`  1\|alice\|bob\|已签收` |
| `ERR|未找到用户\n` | `错误: 未找到用户` |

**关键设计**：菜单函数（`userMenu()` / `adminMenu()` / `courierMenu()`）是**阻塞的**——登录进入、退出登录返回，无需维护复杂的"当前状态"变量。

### 4.5 两阶段操作模式

两个业务需要**先查列表 → 再选编号提交**：

```
userReceivePackage():
  ① sendRequest(RECEIVE_PACKAGE, {})        → Server 返回待签收列表
  ② printResponse(response)
  ③ cin >> "1,2"                             ← 用户输入编号
  ④ sendRequest(RECEIVE_PACKAGE, {"1,2"})   → Server 执行签收

courierCollect():
  ① sendRequest(COURIER_COLLECT, {})         → Server 返回待揽收列表
  ② printResponse(response)
  ③ cin >> "0,1"                             ← 用户输入编号
  ④ sendRequest(COURIER_COLLECT, {"0,1"})   → Server 执行揽收
```

Server 端处理**同一命令两种语义**：

```cpp
// 参数为空 → 返回列表
// 有参数    → 执行操作
if (cmd == CMD_COURIER_COLLECT)
    return handleCourierCollect(courierId, params.empty() ? "" : params[0]);
```

### 4.6 Client 的简单性

对比 Server 和 Client 的复杂度：

| 维度 | Server | Client |
|------|--------|--------|
| 线程模型 | 多线程（主线程 + N 工作线程） | **单线程** |
| 锁 | `CRITICAL_SECTION` | **无锁** |
| 请求量 | 同时处理 N 个客户端 | 处理 1 个用户输入 |
| 状态管理 | 每个线程维护 userType + sessionUsername | **菜单栈** 天然管理状态 |
| 数据持久化 | `DataManager` + 6 个文本文件 | **无** |
| 业务逻辑 | ~30 个 handler 函数 | **拼请求→发→收→展示** |
| 错误处理 | try-catch 保护整条链 | 检查 `ERR` 前缀 |

这也是 **CS 架构的核心哲学**——把复杂性集中在 Server，Client 保持轻薄。

## 五、三者协同的完整数据流

以"alice 查询余额"为例：

```
── Client 端 ──                      ── Server 端 ──

1.  cin 读取用户选择 "查询余额"

2.  buildRequest(CMD_GET_BALANCE)
    → "GET_BALANCE\n"                    ← Protocol.h

3.  sendRequest("GET_BALANCE\n")
    ── TCP :8888 ──────────────────→  4. recv() → "GET_BALANCE\n"

                                       5. processRequest()
                                          解析 cmd="GET_BALANCE"
                                          params=[]

                                          EnterCriticalSection

                                          userType==1
                                          dispatchUserCommand()
                                          handleBalanceQuery("alice")
                                          findUser("alice") → 余额 176

                                          LeaveCriticalSection

                                       6. buildOkResponse("余额：176 元")
    ←────────────────────────────────     → "OK|余额：176 元\n"  ← Protocol.h

7.  receiveResponse()
    → "OK|余额：176 元\n"

8.  printResponse()
    去掉 "OK|"
    cout << "余额：176 元"

9.  用户看到结果
```

**整个过程只有 4 和 6 步涉及网络传输**，而通信协议层的文本格式保证了这些步骤可以用 telnet / Wireshark / 日志肉眼追踪。

## 六、流程图总览

### 6.1 服务端分发的 4 层路由

```
                                    processRequest()
                                           │
                              ┌────────────┼────────────┐
                              │            │            │
                         未登录 (0)      用户 (1)    管理员 (2)  快递员 (3)
                              │            │            │          │
                     dispatchUnauth  dispatchUser  dispatchAdmin  dispatchCourier
```

### 6.2 客户端登录 → 业务操作流程

```
 主菜单
    │
    ├─ 用户注册 ──→ REGISTER ──→ 直接返回结果
    │
    ├─ 用户登录 ──→ LOGIN|user|... ──→ userMenu()
    │                                      │
    │                                      ├─ 余额查询 → GET_BALANCE
    │                                      ├─ 充值 → RECHARGE
    │                                      ├─ 发送快递 → SEND_PACKAGE
    │                                      ├─ 接收快递 → RECEIVE_PACKAGE (两阶段)
    │                                      ├─ 查询快递 → QUERY_SENT / RECEIVED / BY_ID / BY_TIME
    │                                      ├─ 修改密码 → CHANGE_PWD
    │                                      └─ 退出登录 → LOGOUT → 返回主菜单
    │
    ├─ 管理员登录 ──→ LOGIN|admin|... ──→ adminMenu()
    │
    └─ 快递员登录 ──→ LOGIN|courier|... ──→ courierMenu()
```

### 6.3 两阶段操作详细流程

```
userReceivePackage()
  │
  ├─ 阶段一: 获取待签收列表
  │    sendRequest(RECEIVE_PACKAGE, {})        ← 空参数
  │    receiveResponse() → 展示列表
  │
  ├─ 用户输入: "1,2"
  │
  └─ 阶段二: 执行签收
       sendRequest(RECEIVE_PACKAGE, {"1,2"})  ← 带参数
       receiveResponse() → 展示结果

Server 端:
  handleReceivePackage(sessionUsername, params[0])
    if params.empty()
      return 待签收列表                        ← 阶段一
    else
      for each index in params
        签收 packages[index]                   ← 阶段二
      return "已签收 N 个包裹"
```
