# 物流管理系统 — 从零到完成的工程步骤

## 项目概述

一个 **C++ 客户端-服务器（CS架构）** 的物流管理系统，采用 **TCP Socket** 通信、**多线程** 并发处理、**OOP 多态** 设计，支持用户、管理员、快递员三种角色的完整物流业务流程。

## 步骤详解

### 步骤 1：项目规划与目录搭建

- 创建 `topic3/` 目录
- 规划三层架构：**数据模型层** → **业务逻辑层** → **网络通信层**
- 建立 `include/`（头文件）、`src/`（源文件）、`server/`、`client/` 子目录

### 步骤 2：数据模型层 — 人员类体系

构建面向对象的继承体系：

```
Person (基类)
├── username_ / name_ / password_ / balance_
├── GetUsername() / GetName() / GetBalance()
├── CheckPassword() / SetPassword()
├── AddBalance() / DeductBalance()
│
├── User : Person          # 普通用户
│   ├── phonenum_ / address_
│   ├── GetPhonenum() / GetAddress()
│   └── Recharge()
│
├── Admin : Person          # 管理员
│   └── AddCompanyBalance()
│
└── Courier : Person        # 快递员
```

**涉及文件：**
- `include/Person.h` + `src/Person.cpp` — 基类实现
- `include/User.h` + `src/User.cpp` — 用户类（两个构造函数：注册用 / 加载用）
- `include/Admin.h` + `src/Admin.cpp` — 管理员类
- `include/Courier.h` + `src/Courier.cpp` — 快递员类（`username_` 自动拼接为 `"courier" + id`）

### 步骤 3：数据模型层 — 包裹多态体系

使用 **纯虚函数** 实现多态计费：

```
Package (抽象基类)
├── packageId_ / sender_ / receiver_ / sendTime_ / receiveTime_
├── status_ (0=待揽收, 1=待签收, 2=已签收)
├── description_ / courierId_
├── virtual GetPrice() const = 0   ← 纯虚函数
├── IsWaitingCollect() / IsWaitingSign() / IsSigned()
├── Sign() → status_ 1→2
│
├── FragilePackage : Package   # 易碎品 — 8元/kg
│   ├── weight_
│   └── GetPrice() → 8.0 * weight_
│
├── BookPackage : Package      # 图书 — 2元/本
│   ├── count_
│   └── GetPrice() → 2.0 * count_
│
└── NormalPackage : Package    # 普通 — 5元/kg
    ├── weight_
    └── GetPrice() → 5.0 * weight_
```

**涉及文件：**
- `include/Package.h` + `src/Package.cpp` — 抽象基类
- `include/FragilePackage.h` + `src/FragilePackage.cpp`
- `include/BookPackage.h` + `src/BookPackage.cpp`
- `include/NormalPackage.h` + `src/NormalPackage.cpp`

**关键设计：**
- 服务端存储时使用 `vector<Package*>` 多态指针数组
- 保存文件时用 `dynamic_cast` 判断实际类型，写入 `type` 字段（1=易碎, 2=图书, 3=普通）
- 加载文件时根据 `type` 字段反序列化为对应的子类对象

### 步骤 5：通信协议层 — Protocol.h

定义客户端与服务端之间的文本协议。

**涉及文件：** `include/Protocol.h`

**协议格式：**

```
请求: COMMAND|param1|param2|...\n
成功: OK|message\n
      data_line1\n
      data_line2\n
      END\n
失败: ERR|message\n
```

**关键定义：**

```cpp
const char DELIMITER = '|';
const std::string END_MARKER = "END";
const std::string OK_PREFIX = "OK";
const std::string ERR_PREFIX = "ERR";
```

**辅助函数：**
- `buildRequest(cmd, params)` — 构建请求字符串
- `buildOkResponse(msg)` — 构建成功响应
- `buildErrResponse(msg)` — 构建错误响应
- `buildDataResponse(msg, data)` — 构建带数据的成功响应

### 步骤 6：服务端核心 — TCP 多线程服务器

**涉及文件：** `include/Server.h` + `src/Server.cpp` + `server/main.cpp`

**架构设计：**

```
┌─────────────────────────────────┐
│         Server (主线程)          │
│  listenSocket_ → accept() 循环   │
│          ↓ 每连接一个线程          │
│  ┌──────┬──────┬──────┬──────┐  │
│  │Thr#1 │Thr#2 │Thr#3 │ ...  │  │
│  │handle │handle│handle│      │  │
│  │Client │Client│Client│      │  │
│  └──────┴──────┴──────┴──────┘  │
│         CriticalSection         │
│         保护 DataManager         │
└─────────────────────────────────┘
```

**关键实现：**

1. **Winsock 初始化** — `WSAStartup()` → `socket()` → `bind()` → `listen()`
2. **多线程处理** — `accept()` 后 `CreateThread()` 为每个客户端创建线程
3. **线程安全** — `CRITICAL_SECTION` 保护所有数据操作
4. **请求分发链：**

```
recv() → processRequest()
          ├── 未登录 → dispatchUnauthCommand()
          │             ├── LOGIN → handleLogin()
          │             ├── REGISTER → handleRegister()
          │             └── EXIT → Goodbye
          ├── 用户 → dispatchUserCommand()
          │             ├── SEND_PACKAGE → handleSendPackage()
          │             ├── RECEIVE_PACKAGE → handleReceivePackage()
          │             ├── QUERY_SENT / QUERY_RECEIVED ...
          │             ├── GET_BALANCE / RECHARGE / CHANGE_PWD
          │             └── ...
          ├── 管理员 → dispatchAdminCommand()
          │             ├── ADMIN_SHOW_USERS / PACKAGES / BALANCE
          │             ├── ADMIN_ADD / REMOVE_COURIER
          │             ├── ADMIN_ASSIGN_COURIER
          │             └── ADMIN_QUERY_* ...
          └── 快递员 → dispatchCourierCommand()
                        ├── COURIER_MY_TASKS / COLLECT
                        ├── COURIER_MY_RECORDS
                        ├── COURIER_BALANCE
                        └── COURIER_CHANGE_PWD
```
5. **自动保存** — 执行写操作命令后自动调 `saveData()`

**服务端入口（`server/main.cpp`）：**
```cpp
Server server(8888);
server.start();
```

### 步骤 7：业务处理器

三个文件分别实现三角色的业务逻辑。

| 文件 | 角色 | 核心功能 |
|------|------|---------|
| `src/UserHandlers.cpp` | 用户 | 登录/注册/发快递/签收/查询/充值/改密 |
| `src/AdminHandlers.cpp` | 管理员 | 查看用户/包裹/余额、增删快递员、分配任务、高级查询 |
| `src/CourierHandlers.cpp` | 快递员 | 查看任务/揽收/记录/余额/改密 |

**核心业务逻辑：**

- **发送快递**：检查余额 → 按类型计算价格 → 扣除费用 → 公司入账
- **签收快递**：查询待签收列表 → 选择签收 → 记录签收时间
- **快递员揽收**：分配任务 → 揽收 → 获取佣金（50%运费） → 公司扣除佣金
- **管理员查询**：支持按寄件人/收件人/单号/时间段（日/月/范围）查询

### 修改 1：金额输出统一保留 1 位小数

**背景：** 大部分金额输出已使用 `std::fixed << std::setprecision(1)`，但有 3 处遗漏。

**涉及文件：** `src/AdminHandlers.cpp`

| 行 | 函数 | 修改前 | 修改后 |
|---|------|--------|--------|
| 15 | `handleAdminShowUsers` | `<< user.GetBalance()` | `<< std::fixed << std::setprecision(1) << user.GetBalance()` |
| 46 | `handleAdminShowCouriers` | `<< courier.GetBalance()` | `<< std::fixed << std::setprecision(1) << courier.GetBalance()` |
| 56 | `handleAdminShowCourierDetail` | `<< c->GetBalance()` | `<< std::fixed << std::setprecision(1) << c->GetBalance()` |

**效果：** 全站 13 处金额输出统一为 1 位小数（如 `100.0` 而非 `100` 或 `100.000000`）。

---

### 修改 2：禁止同一账号重复登录

**背景：** 服务端不追踪在线状态，同一账号可在多个客户端同时登录。

**设计：** 在 Server 中新增 `onlineSessions_` 映射表 (`map<string, int>`)，以 `"user:用户名"` / `"admin:admin"` / `"courier:id"` 为键标记在线账号。

**涉及文件及改动：**

#### `include/Server.h`
- 添加 `#include <map>`
- 新增成员 `std::map<std::string, int> onlineSessions_`
- 新增辅助方法声明：
  - `static std::string makeAccountKey(const std::string& username, int userType)`
  - `void removeOnlineSession(const std::string& key)`

#### `src/UserHandlers.cpp` — `handleLogin()`
三路登录（用户/管理员/快递员）均在密码验证通过后、返回成功前增加检查：

```cpp
std::string key = makeAccountKey(sessionUsername, userType);
if (onlineSessions_.find(key) != onlineSessions_.end())
    return buildErrResponse("该账号已在其他客户端登录");
onlineSessions_[key] = 0;
```

#### `src/Server.cpp`

| 位置 | 改动 |
|------|------|
| `handleClient` 断开处 | 在 `recv ≤ 0` 分支中，若非空 session 则调用 `removeOnlineSession()` 清理 |
| `processRequest` LOGOUT | 先清理在线记录，再重置 `userType` / `sessionUsername` |
| 新增 `makeAccountKey()` | 按类型拼接键名：`"user:"` / `"admin:"` / `"courier:"` + 用户名 |
| 新增 `removeOnlineSession()` | 在临界区保护下从 `onlineSessions_` 中 `erase` 指定键 |

**行为变化：**
- 账号已在其他客户端登录 → 新登录被拒绝，返回 `"该账号已在其他客户端登录"`
- 正常退出 / 断开 / 登出 → 账号自动释放，可重新登录
- 所有映射操作在临界区保护下，线程安全

### 修改 3：客户端自动重连

**背景：** 服务器关闭后，客户端连接断开后无法恢复，需要手动重启客户端。

**设计：** Client 记住连接地址，检测到连接断开后自动重连（最多 5 次，间隔 2 秒）。

**涉及文件及改动：**

#### `include/Client.h`
- 新增成员 `std::string host_`、`int port_`（保存连接参数）
- 新增方法 `bool reconnect(int maxRetries = 5, int delaySec = 2)`

#### `src/Client.cpp`

| 位置 | 改动 |
|------|------|
| `connect()` | 成功后保存 `host_` 和 `port_` |
| `sendRequest()` | 发送失败时标记 `connected_ = false` |
| `receiveResponse()` | `recv ≤ 0` 时标记 `connected_ = false`，返回 `"连接断开"` |
| 新增 `reconnect()` | 关闭旧 socket → 循环重连（最多 5 次，每次间隔 2 秒）→ 成功返回 true |
| `run()` 主菜单循环 | 顶部检测 `!connected_` → 自动调用 `reconnect()`，失败则退出 |
| `userMenu()` 循环 | 同上，重连失败则返回主菜单 |
| `adminMenu()` 循环 | 同上 |
| `courierMenu()` 循环 | 同上 |

**效果：**
- 服务器关闭后，客户端下次操作时自动检测断线
- 弹出 `>>> 与服务器连接断开，正在自动重连...` 提示
- 自动重试 5 次（每次间隔 2 秒），重连成功后恢复操作
- 任意菜单层级（主菜单/用户菜单/管理员菜单/快递员菜单）均可触发重连
